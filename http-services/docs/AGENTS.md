## 维护要求

- 先阅读并遵循 [文档规范与导航](README.md)，按实际受众和版本组织资料；模板不预建订单、资金、供应商等业务文档。
- 保留 `feat/`、`update/`、`prd/`、`share/`、`origin/` 通用目录骨架，空目录使用 `.gitkeep`；实际版本和接入面按需创建，不把目录占位当作业务实现或已完成文档。
- 接口说明须独立可接入，写全路径、方法、身份、参数、响应、嵌套字段、默认／空值／枚举／单位、错误及示例，不让调用方通过源码补齐。
- 页面说明、数据库设计、后端规则、前端接口与系统间协议分别承担各自职责；只描述已确定的有效契约，明确区分草稿、发布与验证状态。
- 新增或修改文档时维护每份受改文档自己的更新记录，并更新必要导航。
- 移动资料同步链接、生成器及测试引用；纯文档变更检查引用和示例，行为变更同时验证实现。
