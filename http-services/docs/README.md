## 目录职责

模板预置以下通用文档目录，空目录通过 `.gitkeep` 纳入 Git。实际版本、接入面和文档按项目需要创建；目录占位不表示已有业务实现，也不要求迁移已有历史资料。

```text
docs/
├── README.md
├── AGENTS.md
├── feat/
│   └── .gitkeep
├── update/
│   └── .gitkeep
├── prd/
│   └── .gitkeep
├── share/
│   └── .gitkeep
├── origin/
│   └── .gitkeep
└── troubleshooting/
    └── request-logging.md
```

`.gitkeep` 只用于保留空目录；加入实际文档后可以删除对应占位文件。不要用空 Markdown 文件冒充已编写文档，也不要预设与真实项目无关的版本号或业务名称。

| 目录 | 读者与职责 |
| --- | --- |
| `feat/<版本>/` | 当前版本的需求、数据设计、后端规则及完整接口变更；版本号由真实项目确定。 |
| `update/` | 历史版本接口说明与既有前端接入资料的保留入口；新版本完整资料统一放 `feat/<版本>/`。 |
| `prd/` | 既有需求、内部设计和实施参考资料的保留入口；新版本设计按下方四类职责归入 `feat/<版本>/`。 |
| `share/<接入面>/` | 对接方可独立使用的系统间协议，包含鉴权、参数、响应、错误与操作流程。 |
| `origin/` | 上游原始文档与来源，保留原文格式；适配分析放对应版本的后端说明。 |
| `troubleshooting/` | 已有能力的排障步骤、日志含义与运行边界。 |

`update/`、`prd/` 初始仅保留目录入口，真实项目有相应历史资料时继续在原位置维护；不要求一次性改名或回迁。README 负责导航，具体文档负责完整说明，不维护两套互相矛盾的权威契约。

## 版本文档按受众拆分

在 `feat/<实际版本>/` 下按需要编写以下文档；只有空的版本目录时也可以先用 `.gitkeep` 保留。

| 文档 | 必须说明 |
| --- | --- |
| `前端PRD.md` | 页面名称、用途、入口、可见字段、按钮条件与跳转；用简单中文说明页面。无前端的版本不创建此文档。 |
| `数据库设计.md` | 表、字段、类型、约束、关联、索引及迁移方案；涉及 SQL 时随版本保存，可放 `migrations/` 子目录。无数据结构变更时不建空文档。 |
| `后端PRD.md` | 范围、规则、状态、成功依据、处理流程、依赖、事务边界、超时与异常恢复。 |
| `接口文档.md` | 按页面或调用身份写全接口，记录新增、修改、删除及前后差异，让调用方可直接接线。纯服务端接入也须标明调用身份及用途。 |

按编写进度创建所需文档，导航注明“草稿／已评审／已发布”等真实状态；未编写不能标记为完成。前端说明不混入事务、锁、任务调度、消息 ACK 等内部实现；这些属于后端或数据库设计。签名、回调及其他系统间协议放在对应 `share/`，不让前端通过源码或服务端协议补齐页面接线信息。

## 接口文档完整性

- 每个接口说明用途、完整路径、HTTP 方法、登录身份或鉴权方式，以及适用版本和发布状态。
- 参数和响应逐项说明字段名称、类型、含义、必填／必返、默认值、可空或可省略规则、范围、枚举与单位；路径、Header、Query、Body、嵌套对象、数组元素和分页同样完整。无参数明确写“无”。
- 提供可核对的请求、成功和错误响应示例。字段复用可引用本文内的完整表格，不能以“同原接口”“字段不变”让调用方自行查源码。响应示例体现模板实际的 HTTP 200 与 `code/status` 策略。
- 说明调用方需要处理的错误、重试、重复提交、超时与状态变化。同步接口写清本次请求完成的操作和成功依据；只有已确定采用异步契约时才描述任务状态、查询与通知，不为了说明实现而新增异步流程。
- `share/` 必须能独立完成接入，写全凭据配置、鉴权、必要字段、规范化算法、错误、幂等、状态与流程；仅在协议实际使用时描述签名和消息等内容。不得依赖内部 PRD 或源码补全，不暴露无关后台设置、私有表结构或测试流水账。
- 已发布契约保持兼容；不能兼容时明确新增版本或入口以及迁移要求。草稿不伪装成已发布协议，单元测试或替身验证不能写成真实部署或联调通过。

## 更新记录要求

新建或修改受维护文档时，在该文档的“更新记录”章节记录更新时间、对读者有用的变更概述及详细章节链接。沿用已有记录，按时间倒序补充；同日不同事项可以分开记录，不能只改顶部日期。上游原稿保持原文，来源与适配说明另行维护。

统一表头为 `更新时间 | 更新内容（概述） | 对应详细章节`。纯粹的任务流水账和测试终端输出不作为长期设计文档；保留可复用规则、接口契约及必要验证边界。

## 维护与校验

- 接口变化同步实现、对应测试、所属版本接口文档及受影响的 `share/`；页面、规则或数据结构变化更新对应文档。
- 新文档加入导航；移动文件同步 Markdown 链接、目录入口、生成器和测试引用。保留已有资料和他人未提交编辑。
- 示例按真实路由、绑定参数和 DTO 核对；JSON 示例须可解析，不使用省略号伪装完整数据。模板中的假设性业务示例应标明“示意”，不作为已实现接口。
- 检查链接与锚点、字段和示例的一致性；纯文档变更不重复运行无关全仓测试。涉及代码行为时运行相关测试与模板的 `make verify`。
